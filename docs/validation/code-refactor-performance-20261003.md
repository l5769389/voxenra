# 代码重构与交互性能优化 · 2026-10-03

## 范围与结果

本轮基于 `main / 6e6af6a` 及已有未提交修改，保留此前的空间验证和分割显示功能。
重点整理分割显示与编辑历史两条频繁执行的路径。没有改变 MTF/FWHM 公式、
分割统计定义、工作区文件格式、界面布局或发布版本，也没有推送或打包。

### 实现调整

- 从 `MprVoiController` 提取 `SegmentationOverlayRenderer`，集中管理切面采样、
  显示样式和 PNG 缓存。保留现有 QML 图像接口；同一画笔样本被重复读取时复用显示图。
- 缓存按视口和分割管理，最多 64 项、32 MiB 的二维显示数据。通过弱引用识别源掩膜，
  不持有过期三维掩膜；取消、提交、时相切换和销毁时释放对应缓存。
- 新增明确的 `editsChanged` 信号。只有提交绘制、修改分割参数、名称、颜色、显隐及删除等
  数据编辑触发撤销历史检查；显示模式、透明度、选择、草稿取消和后台结果刷新不触发。
- 编辑状态签名复用工作区编码器的类型校验，以打包掩膜的 SHA-256 代替压缩及 Base64。
  每次读取真实内容，仍能发现原地像素修改；只有实际历史快照执行压缩。
  写入快照失败时不破坏当前历史或清空重做记录。
- 分割切面采样按行块计算，保留原来的坐标运算顺序和半体素取整规则，减少大尺寸临时数组。

## 性能对比

同一台 Apple Silicon Mac、Python 3.13.14，使用固定随机种子的合成掩膜：
`128 × 256 × 256`，8,388,608 体素。预热后通常重复 9 次，切面采样重复 5 次，表中为中位数。

| 项目 | 修改前 | 修改后 |
|---|---:|---:|
| 无变化的撤销历史检查 | 81.31 ms | 0.53 ms |
| 显示参数回调及历史检查（不含 QML 绘制） | 114.73 ms | 0.014 ms |
| 同一画笔预览重复取图 | 11.03 ms | 0.003 ms |
| 512 × 512 分割切面采样 | 5.93 ms | 2.37 ms |
| 1024 × 1024 分割切面采样 | 15.01 ms | 6.00 ms |
| 2048 × 2048 分割切面采样 | 56.67 ms | 19.35 ms |
| 2048 × 2048 采样分配峰值 | 224.06 MiB | 8.62 MiB |

分配峰值由 `tracemalloc` 测得，包含输出掩膜与计算临时数组，不含输入体数据或整个应用的内存。
这些是特定合成数据的 CPU 基准，不代表整应用帧率、所有患者数据或 Windows 机器的收益。
分割实际提交仍需保存可撤销快照和计算统计，未承诺所有绘制步骤都变为上述缓存命中耗时。

基准脚本：`tests/manual/benchmark_segmentation_interaction.py`。
原始结果与测试日志位于本地 `build/refactor-performance/`，汇总数值和代码校验值见
[机器可读报告](code-refactor-performance-20261003.json)。
