# 分割精修与 Slicer 交换验证（2026-09-28）

验证对象为本地 `main` 工作目录中的未发布修改。运行环境为 macOS、Python 3.13、Qt 6.11.1 和已安装的 3D Slicer 5.12.4；未打包、推送或发布。

## 结论与修复

三组数据通过 NRRD 双向逐体素、几何、区域元数据及统计核对。真实 MR 的界面绘制、擦除、撤销、重做与工作区重启恢复通过检查。

发现并修复：工作区原先保留分割掩膜，但没有保留精修模式、笔刷尺寸、相对尺寸模式、作用范围和所选区域。现在以可选、独立版本的 `segmentationTool` 保存这些状态，旧工作区使用默认值。恢复不会提交笔画或启动播放；工具状态变化会标记工作区未保存，单纯显示刷新不会。

## Slicer 独立核对

| 数据 | 尺寸（层 × 行 × 列） | 导出区域体素数 | Slicer 编辑后回传体素数 |
| --- | --- | --- | --- |
| 本地 MR | 192 × 256 × 256 | 1198 / 1198 / 0 | 1199 / 1198 / 0 |
| P113 CT | 99 × 512 × 512 | 410 / 410 / 0 | 411 / 410 / 0 |
| 合成倾斜体积 | 31 × 43 × 51 | 846 / 846 / 0 | 847 / 846 / 0 |

每组包含两个重叠区域和一个空区域；使用本软件画笔算法生成笔画并擦除局部。合成体积包含 23° 倾斜和 2.4 / 0.7 / 0.5 mm 各向异性间距。

- Slicer 加载本软件导出的 `source.nrrd` 和 `segmentation.seg.nrrd`，核对全部源体素、LPS/RAS 几何、每个区域的完整二值掩膜、名称、颜色及空区域。
- 对真实 MR 和 CT，额外通过 Slicer 自带 SimpleITK/GDCM 独立解码原始 DICOM，源体素及几何与导出体数据一致。MR 的目录发现未找到序列，使用明确文件列表解码；像素及几何检查仍由 ITK/GDCM 完成。
- Slicer 的 Segment Statistics 与本软件的体素数、体积、均值、最小值和最大值吻合。Slicer 此路径采用样本标准差，本软件采用总体标准差；按 `SD_population = SD_sample × sqrt((N−1)/N)` 统一定义后吻合，没有修改本软件统计公式。
- 在 Slicer 中向首个区域加入一个已知体素并改名，保存后由本软件重新读取；三组数据的掩膜逐体素、名称、颜色和空区域均一致。
- 实际打开 Slicer GUI 加载 MR 与分割，三平面可见分割叠加且方向、位置正常。

这验证的是已测试数据的交换和统计正确性，不表示两款软件的画笔边界采样规则完全相同，也不代表全部 NRRD 变体均受支持。

独立脚本：`tests/manual/verify_nrrd_slicer.py`。本地输入、Slicer 日志和双向比较结果位于 `build/refinement-readiness/`，医疗影像未加入仓库，也未上传。

## 绘制、闪烁与恢复

- macOS 实际 MR 界面操作：绘制后 1288 个体素，擦除后 947，撤销恢复 1288，重做恢复 947；新增另一区域为 1075 个体素，自动使用不同颜色。
- 保存工作区并退出后重新启动，恢复 947 / 1075 个体素及各区域元数据。
- 新增独立进程恢复测试，校验掩膜、位置、名称、颜色、显隐、选中区域、橡皮模式、毫米与相对尺寸及球形范围；恢复后无草稿、播放暂停且工作区不产生虚假修改。
- 遮罩渲染回归覆盖 56 次擦除/恢复更新、392 帧采样：未改动像素不消失、不叠加透明度，被擦除像素正确移除。它不能代替所有显卡和驱动下的闪烁验证。
- 其他回归覆盖各向异性笔刷、连续笔画、六邻域连通操作、取消、工作区兼容、撤销重做、错误网格及取消导出。

## 测试与剩余边界

测试按文件独立进程运行，结果保存在 `build/refinement-readiness/{regression,fixes,final,manual-recheck}/`。初轮 150 项通过、2 项跳过；新增恢复回归曾复现工具状态丢失，修复后重新验证。按每个文件最后一次完整运行汇总为 **162 项通过、2 项跳过**，详见本地 `latest-results.json`。此通过数不表示下述间歇性崩溃已解决。

两个跳过项分别为需原生桌面的首次 tooltip 定位测试，以及现有明确排除的 PET 专用强度视图联动调窗测试。它们不作为通过项。

**手册 GUI 测试仍有间歇性原生崩溃，建议发布前查明。** 最后一轮 `test_manual.py` 在第 11 项创建 MPR 页签时退出码为 -11，栈顶是 `WindowWorkspaceController._select` 发出 `activeTabChanged` 信号；尚不能判定是 Qt/PySide 生命周期、测试环境或应用问题。该单项随后单独运行通过，整个文件再运行也 12 项通过。保留 `final/002-test_manual.log`，不把重跑通过当作根因修复。

**尚未进行 Windows 实机/低性能显卡验证。** 当前结果支持本次 macOS 核心精修与交换流程，但正式发布前仍应在 Windows 检查连续擦除、撤销重做、弹出层反复切换和工作区重启恢复。

## 发布前补充复核

原生崩溃报告定位到 `QQmlPropertyCache::append`，PySide 属性日志显示在读取 `EditHistoryController` 时触发。该类的 `capture` 和 `schedule` 原先没有声明 Qt 槽，连接信号后产生临时实例元对象（方法数 9，类静态元对象为 7）。已将两者声明为固定 `@Slot()` 并增加静态元对象回归；修复后原手册整组连续三轮通过，多窗口及分割交换回归通过。发布验证与最终全量结果见本次发布记录。
