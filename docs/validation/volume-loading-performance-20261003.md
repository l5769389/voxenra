# 体数据加载重构与内存优化 · 2026-10-03

## 本轮范围

在上一轮分割显示和撤销历史优化之后，继续整理 DICOM 解码缓存、体数据装配和源文件校验。
基于 `main / 6e6af6a` 及现有未提交修改，不改变空间变换、逐帧强度换算、PET SUV 公式、
MTF/FWHM 公式、工作区格式或界面布局。没有提交、推送、打包或发布。

- 将像素读取及定量元数据汇总从 `VolumeManager._build_volume` 提取到 `_read_volume_frames`。
  几何校验和排序仍在读取前完成，读取后建立同样的患者坐标映射。
- 预分配连续的 float32 体数组，每次只写入一帧，避免保留全部切片后再 `stack` 出第二份体数据。
- PET BQML 单独保留原始数值。任意切片缺少 SUV 必需参数时，整组回退到原始单位，
  完成后的显示体与原始体共享缓冲区；不混合 SUV 与 Bq/ml。
- 解码缓存同时限制为最多 12 帧、64 MiB；保留一个超限的当前帧，避免调窗时反复解码。
  顺序构建体数据时仅保留当前帧。含编码像素的 Enhanced 头部缓存继续使用原有独立限额。
- 同一次体数据指纹计算中，一个 Enhanced 文件只读取一次文件状态；下次计算仍重新读取，
  因而可以检测文件被替换。指纹字段和哈希格式保持不变。

## 性能对比

同一台 Mac、Python 3.13.14，使用实际写入磁盘并经扫描器分组的合成 DICOM。
每组 `128 × 512 × 512`；文件名和 InstanceNumber 与空间顺序相反，包含逐帧小数缩放。
PET 回退案例在最后一帧缺失体重。输入校验值与完整结果校验值见配套 JSON 报告。

| 项目 | 修改前 | 修改后 |
|---|---:|---:|
| CT 加载分配峰值 | 256.26 MiB | 133.12 MiB |
| PET SUV 加载分配峰值 | 512.47 MiB | 262.24 MiB |
| PET 回退原始单位的加载峰值 | 385.44 MiB | 262.24 MiB |
| PET 回退后保留的像素内存 | 256 MiB | 128 MiB |
| CT 加载中位耗时 | 63.26 ms | 62.36 ms |
| PET SUV 加载中位耗时 | 81.03 ms | 80.04 ms |
| PET 回退加载中位耗时 | 82.24 ms | 78.74 ms |

主要收益是降低内存峰值，耗时变化较小，不据此宣称明显加速。计时使用预热文件缓存后的三次
中位数，包含 `get_or_build` 的源文件校验、解码、数值换算和装配，不含文件生成、初次扫描或
GPU 显示。内存由 `tracemalloc` 单独测量，反映 Python/NumPy 分配，不是整个应用 RSS。
上述结果不代表冷磁盘、所有患者数据、压缩编码或 Windows 集显的性能。

基准脚本：`tests/manual/benchmark_volume_assembly.py`。本地原始日志：
`build/volume-loading-refactor/`。
