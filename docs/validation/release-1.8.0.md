## 回归中发现的问题

- 撤销控制器信号连接曾动态扩展 QObject 元对象，导致 QML 对象暴露时偶发原生崩溃。为 `capture`、`schedule` 声明静态 Qt Slot，并增加元对象稳定性回归；手册／MPR 切换文件连续三轮通过。Windows 随后在 PET 慢重建场景发现访问冲突；诊断发现 PET 的 `snapshotCommitted(object)` 仍为历史控制器新增动态槽，补齐 `schedule(object)` 重载。新增 CT、PET 与融合页签的静态元对象检查，并把阅片加载用例加入 Windows 三轮压力检查。修复前单独 PET 用例稳定检测出多余动态槽，修复后本地加载用例三轮及分割交换共 74 项通过。
- 工作区恢复期间撤销／重做属性可能暂时缺失，QML 快捷键现在将其明确转换为布尔值。
- 遮罩稳定性用例原先仅固定等待 50 ms，可能在第三个平面尚未创建时采样。现等待三个遮罩加载完成后验证整个笔画期间对象身份和纹理就绪状态，不削弱绘制／擦除／撤销重做断言。
